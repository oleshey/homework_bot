# Homework Bot

Telegram-бот для отслеживания статуса проверки домашней работы на сервисе **Яндекс Практикум**.

Бот раз в 10 минут опрашивает API сервиса «Практикум Домашка» и сообщает в Telegram, что происходит с вашей домашней работой: взята ли она в ревью, проверена ли, а если проверена — принял её ревьюер или вернул на доработку.

## Возможности

- опрашивает API сервиса «Практикум Домашка» раз в 10 минут (`RETRY_PERIOD = 600` секунд);
- при обновлении статуса анализирует ответ API и отправляет уведомление в Telegram;
- логирует свою работу в стандартный поток `sys.stdout` и в файл;
- сообщает о важных проблемах сообщением в Telegram;
- при повторяющихся ошибках отправляет сообщение об ошибке в Telegram только один раз (в лог при этом пишется каждая неудачная попытка).

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone <адрес вашего репозитория>
cd homework_bot
```

### 2. Создание и активация виртуального окружения

```bash
python -m venv venv
source venv/bin/activate        # Linux / macOS
venv\Scripts\activate           # Windows
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка переменных окружения

Создайте в корне проекта файл `.env` и заполните его:

```ini
PRACTICUM_TOKEN=<токен от API Практикум Домашка>
TELEGRAM_TOKEN=<токен вашего Telegram-бота>
TELEGRAM_CHAT_ID=<ваш Telegram chat_id>
```

| Переменная | Описание |
| --- | --- |
| `PRACTICUM_TOKEN` | OAuth-токен для доступа к API сервиса «Практикум Домашка» |
| `TELEGRAM_TOKEN` | Токен бота, полученный у [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_CHAT_ID` | Идентификатор чата, в который бот будет отправлять сообщения |

> **Важно:** не изменяйте имена переменных окружения `PRACTICUM_TOKEN`, `TELEGRAM_TOKEN` и `TELEGRAM_CHAT_ID` — от них зависят тесты перед ревью. Никогда не коммитьте файл `.env` в репозиторий.

### 5. Запуск бота

```bash
python homework.py
```

Если хотя бы одна обязательная переменная окружения отсутствует, бот залогирует ошибку уровня `CRITICAL` и остановится.

## Как это работает

Основная логика описана в функции [`main()`](homework.py) и выполняется в бесконечном цикле:

1. выполняется запрос к API через [`get_api_answer()`](homework.py);
2. ответ проверяется на соответствие документации через [`check_response()`](homework.py);
3. если есть обновления — извлекается статус работы через [`parse_status()`](homework.py) и отправляется сообщение в Telegram через [`send_message()`](homework.py);
4. бот «засыпает» на `RETRY_PERIOD` секунд и возвращается к пункту 1.

Вспомогательные функции:

- [`check_tokens()`](homework.py) — проверяет доступность всех обязательных переменных окружения;
- [`send_message()`](homework.py) — отправляет сообщение в чат `TELEGRAM_CHAT_ID`.

## Логирование

Каждое сообщение в журнале логов содержит:

- дату и время события;
- уровень важности события;
- описание события.

Пример записи:

```
2021-10-09 15:34:45,150 [ERROR] Сбой в работе программы: Эндпоинт https://practicum.yandex.ru/api/user_api/homework_statuses/ недоступен. Код ответа API: 404
```

Логи выводятся в стандартный поток `sys.stdout` (обработчик `StreamHandler`), а также дублируются в файл `homework.py.log` (обработчик `RotatingFileHandler` с ротацией до 5 файлов по 50 МБ).

Обязательно логируются следующие события:

| Событие | Уровень |
| --- | --- |
| Отсутствие обязательных переменных окружения при запуске | `CRITICAL` |
| Удачная отправка сообщения в Telegram | `DEBUG` |
| Сбой при отправке сообщения в Telegram | `ERROR` |
| Недоступность эндпоинта API | `ERROR` |
| Любые другие сбои при запросе к эндпоинту | `ERROR` |
| Отсутствие ожидаемых ключей в ответе API | `ERROR` |
| Неожиданный статус домашней работы в ответе API | `ERROR` |
| Отсутствие в ответе новых статусов | `DEBUG` |

События уровня `ERROR` не только логируются, но и пересылаются в Telegram, когда это технически возможно. Если ошибка повторяется при каждой попытке, сообщение о ней отправляется в Telegram только один раз.
